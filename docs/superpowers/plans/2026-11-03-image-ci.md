# Production image and CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-ready myjobbot image in GitHub Actions and push it to GHCR (PR 1 of
`docs/superpowers/specs/2026-11-03-packaging-helm-design.md`).

**Architecture:** A two-stage Dockerfile: the build stage installs all dependencies and runs
`next build web` into `web/.next-prod`; the runtime stage keeps today's layout (`npm ci
--omit=dev`) and copies in only `.next-prod`. `entrypoint.sh serve` runs `next start` when
`MYJOBBOT_WEB_MODE=production`, `next dev` otherwise, so compose is unchanged. One workflow builds
on PRs and pushes on `main` and `v*` tags.

**Tech Stack:** Docker Buildx, GitHub Actions (`docker/*` actions pinned by SHA), Next.js 16.

Tests: no TypeScript changes, so no new unit, integration or UI tests (0/0/0). Verification is a
local image build plus a production-mode run against the configured MariaDB.

### Task 1: Two-stage Dockerfile with a production web build

**Files:**
- Modify: `Dockerfile`
- Modify: `web/tsconfig.json` (add `.next-prod` type paths, as for `.next-docker`, so
  `next build` doesn't rewrite the file)

- [ ] **Step 1:** Add `".next-prod/types/**/*.ts", ".next-prod/dev/types/**/*.ts"` to
  `web/tsconfig.json`'s `include`.
- [ ] **Step 2:** Add a `build` stage before the runtime stage:

```dockerfile
FROM node:24.21.0-bookworm-slim AS build
WORKDIR /app
COPY package.json package-lock.json tsconfig.json ./
RUN npm ci
COPY src ./src
COPY web ./web
RUN NEXT_TELEMETRY_DISABLED=1 NEXT_DIST_DIR=.next-prod node_modules/.bin/next build web
```

  and in the runtime stage, after `COPY --chown=node:node web ./web`:

```dockerfile
COPY --from=build --chown=node:node /app/web/.next-prod ./web/.next-prod
```

- [ ] **Step 3:** `docker build -t myjobbot:ci-test .` → succeeds; `git diff web/tsconfig.json`
  shows only the added paths.

### Task 2: Production mode in `serve`

**Files:** Modify: `docker/entrypoint.sh`

- [ ] **Step 1:** In `serve`, after the `MYJOBBOT_HOSTS` check and `cd /app`:

```sh
    if [ "${MYJOBBOT_WEB_MODE:-dev}" = production ]; then
      export NEXT_DIST_DIR=.next-prod
      exec node_modules/.bin/next start web --hostname 0.0.0.0 --port "${MYJOBBOT_PORT:-8080}"
    fi
```

- [ ] **Step 2:** Rebuild, then run against the configured database:
  `docker run --rm --env-file .env -e MYJOBBOT_WEB_MODE=production -e MYJOBBOT_HOSTS=localhost:18080 -e MYJOBBOT_PORT=18080 -v "$PWD/../myjobbot/data:/data:ro" -p 18080:18080 myjobbot:ci-test serve`
  (read-only data so the live data can't be touched). `curl -s -o /dev/null -w '%{http_code}' localhost:18080/`
  → `200`; with `-H 'Host: evil:1'` → `421`.
- [ ] **Step 3:** Document `MYJOBBOT_WEB_MODE` in `.env.example`.
- [ ] **Step 4:** `docker compose config --quiet` passes; commit.
